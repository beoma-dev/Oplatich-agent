# Версии общих правил и skills

Файлы общих правил поставляются из частного beoma-dev/engineering. Каждый проект
хранит .shared-standards.lock.json: версия релиза, полный commit источника, хеш
manifest и хеши только файлов своего набора. Общие review-инструкции входят в
common; дополнительные сервисные правила — в service. Сервисные команды, роли
и исключения остаются в root-инструкциях и .quality/profile.json своего проекта.

## Проверить установленную версию

```bash
python tools/shared_standards.py check
```

Команда без сети сверяет полный состав своего набора и байты файлов с lock.
CI запускает ту же проверку. Она обнаруживает случайную ручную правку или
потерянную копию skill, но не доказывает подлинность вручную изменённого lock,
качество правил или прохождение ревью. Изменения tool/lock проверяются как код.
CI не обращается к частному источнику и не требует межрепозиторного токена.
В публичный проект попадают только его common-файлы и собственная квитанция,
а не manifest со списком частных проектов и не содержимое сервисного стандарта.

## Обновить или откатить

В отдельной ветке задачи клонируй engineering обычным Git с доступом владельца.
Выбери проверенный commit релиза (40 символов SHA), а не main/latest/tag:

```bash
python tools/shared_standards.py sync --source-dir /path/to/engineering --commit FULL_40_CHARACTER_SHA
python tools/shared_standards.py check --source-dir /path/to/engineering
```

sync читает manifest и обычные blobs указанного commit через Git; код из источника
не запускается. Незафиксированные файлы источника не участвуют. Текущая копия должна
совпадать со старым lock: локальные изменения не затираются. Смена набора common/service
требует отдельной миграции. Для отката укажи прежний проверенный commit тем же способом.
Если нужно обновить manifest/состав инструмента, сначала проверь изменение в engineering.

Для первой установки укажи также --repository с именем проекта. Если старые общие
файлы отличаются от релиза, --adopt разрешает их начальную замену. Перед его применением
сохрани и проверь diff существующих файлов. После появления lock --adopt запрещён.
Корневые инструкции, service-checks, профиль сервиса и рабочий код не управляются sync.

Все источники и назначения проверяются до записи; symlink в управляемом пути
отклоняется. Ошибка записи вызывает откат уже записанных файлов. Убийство процесса
или отказ диска могут оставить неполную операцию: проверь Git diff и check, восстанови
предыдущие файлы из Git, затем повтори обновление. Это не транзакция файловой системы.
Не редактируй общие файлы одновременно с sync.

Проверь полный diff, регрессии проекта и минимум два независимых круга ревью
с разбором вопросов. Только затем обычный push проверенного head в main; защиту
main не включать. sync не делает commit/push, не устанавливает hooks и не меняет
сервисы, расписания, секреты или рабочие данные. Обновление шести проектов — шесть
отдельных поставок одного commit, а не атомарная публикация всей организации.
