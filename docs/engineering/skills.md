# Skills Beoma

Навыки поставляются из engineering и проверяются `./check` / shared_standards.py.
Из одного исходника получаются одинаковые SKILL.md в `.agents/skills/` и
`.claude/skills/`; Cursor rule и общий workflow указывают читать этот каталог.
Это проектные инструкции, не установленный marketplace plugin и не pre-push hook.
Присутствие файлов не является доказательством их загрузки конкретным клиентом:
в новой сессии попроси агента назвать найденный skill и его путь, затем проверить
реальную задачу. Автоматический выбор зависит от клиента и соответствия description.

Выбирай навык по задаче, не запускай все для каждой правки:
- `beoma-change`: изменение/исправление, границы, инварианты и критерии приёмки.
- `beoma-review`: независимое ревью, минимум два круга, ответы и exact SHA.
- `beoma-db-change`: SQL-схема/перенос данных, реальные PostgreSQL либо SQLite.
- `beoma-ui-check`: изменяемый интерфейс, состояния/роли/геометрия, до/после.
- `beoma-release`: публикация в main или deployment с раздельными разрешениями.

При наличии дополнительных service skills используй их по описанию и корневым
инструкциям проекта; они не устанавливаются автоматически в чужой профиль.
Существующие `skills/...` по явной ссылке в AGENTS/CLAUDE сохраняют свою роль.

Пример запроса: «Примени beoma-change к этой задаче, назови затронутые инварианты
и выполни ./check». Для релиза: «Примени beoma-release; scope — публикация Git,
без production deployment». Навык не расширяет разрешение владельца, не выдаёт
автоматический approve и не разрешает реальные отправки/миграции ради тестов.

Проверка установленной версии: `python tools/shared_standards.py check`.
Обновление/миграция/откат — [shared-standards.md](shared-standards.md).
Не редактируй поставленные копии вручную. Новые проекты сначала регистрируются
в manifest источника и проходят отдельное ревью; одного создания GitHub repo
для установки skills недостаточно.
