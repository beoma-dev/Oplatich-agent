# Beoma UI check

Изучи правила продукта, существующие компоненты/токены и service-checks.
Определи затронутый сценарий, состояния, роли и реальную платформу. Используй
существующую тестовую браузерную обвязку, когда она есть; не подключай новый
внешний сервис только ради аудита. Если браузер/URL недоступен, отдельно укажи,
какие выводы доказывают статические тесты, а какие остаются непроверенными.

Сними исходное поведение на синтетических данных, затем проверь исправление в
том же сценарии/viewport/теме. Сохрани конкретные до/после: шаги, снимок нужного
участка и измерение проблемы (overflow, обрезка, лишний запрос, ошибка доступа),
без cookies, токенов, ФИО или рабочих записей. Для неизменённого UI screenshots
не нужны только ради отчёта о правилах/CI.

Для затронутых областей проверь:
- empty/loading/error/success и повтор после ошибки; unknown не превращается в zero;
- разрешённые роли, отсутствие входа и прямое обращение к API; скрытая кнопка
  не заменяет серверный запрет. Не объединяй роли разных сервисов;
- 320/390/768/1440 CSS px и промежуточную ширину, где меняется раскладка;
  длинные подписи, zoom и доступные темы, если они относятся к diff;
- клавиатуру, видимый focus, label и имена controls; для диалога Escape, фокус
  внутри и его возврат. Автоматическая проверка не сертифицирует screen reader;
- сохранение фильтра/состояния, быстрые переключения, запоздалый ответ и повторное
  действие, если diff меняет асинхронное взаимодействие.
Для общих UI-компонентов используй доступные Chromium/Firefox/WebKit по правилам
проекта; отсутствие движка отмечай. Не объявляй все браузеры проверенными по одному.

В HTML/CSS-секции, где платформа не исполняет JavaScript, сохраняй это ограничение.
Проверка generated HTML не доказывает поведение санитайзера опубликованной платформы:
используй разрешённый актуальный URL, когда он нужен для вывода. Сам аудит не даёт
разрешения публиковать секцию. Не запускай остановленный сервис ради screenshots.

Запусти относящиеся тесты и `./check`. При геометрическом сбое сравни исходный SHA
с теми же Node/браузером/ОС/шрифтами: существующий baseline fail отмечай отдельно.
Не ослабляй пороги, не выключай тест и не выдавай другой зелёный CI за исправление.
В ревью передай дефект, воспроизведение, diff, доказательства и ограничения;
публикация в main проходит `beoma-review`. Не делай реальные отправки, платежи,
назначения или изменения production ради проверки UI.
