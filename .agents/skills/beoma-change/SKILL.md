# Beoma change

До правок прочитай корневые инструкции, `docs/engineering/agent-workflow.md`
и `docs/engineering/service-checks.md` в репозитории. Команда полного набора —
`./check`; отдельная группа даёт только частичный результат. При наличии сервисного
стандарта и `.quality/profile.json` следуй им; роли и правила соседнего проекта не переноси.

Сформулируй из запроса наблюдаемый результат и границы: чей сценарий меняется,
какие данные/источники/периоды и роли затронуты, как выглядят успех и ошибка.
Сначала найди действующую реализацию, её потребителей и тесты. Отметь конкретные
инварианты, которые diff может нарушить: unknown против zero, исторические даты,
источник истины, доступ, идемпотентность или границы внешних действий.
Не придумывай отсутствующие продуктовые решения. Известное разрешение сохраняется;
спроси только о недостающем решении, без которого зависимая часть не определена,
и продолжай независимую работу. Паузы владельца сохраняются.

Выбери минимальный связный diff и проверяемые критерии: обычный сценарий плюс
нужные границы/ошибки именно этого изменения. Для простых обратимых правок не
создавай тесты, повторяющие реализацию. Если затронуты формула, права, сохранение
или повторная доставка, проверь их поведение на fixtures/изолированном окружении.

Подключай специальные skills по делу: `beoma-db-change` для схемы/переноса данных,
`beoma-ui-check` для пользовательского интерфейса, `beoma-release` для публикации.
Если установлен `beoma-data-contract`, используй его при изменении межсервисного
пакета/формата. Не выполняй все процедуры для любого изменения.

Запиши исходный SHA, затронутые проверки и существующие сбои. Не выдавай отсутствие
Docker/браузера/прав/среды за зелёный пропуск. Для quality gate stage только нужные
файлы, plan/record с реальными командами и случаями; отчёт дополняет тесты.
Перед main используй `beoma-review`; skill не заменяет двух независимых кругов.
В итоге сообщи изменение, точный проверенный head, фактические результаты,
непроверенное и способ отката. Работающий сервис проверяй по масштабу diff;
проверка правил не разрешает запись в рабочую БД, отправки или перезапуск.
