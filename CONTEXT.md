# CONTEXT — выгрузка контекста проекта

Этот документ — «память» проекта: что это, как устроено, какие решения приняты
и почему, что осталось сделать. Актуален на 2026-08-04.

---

## 1. Что это

**invoice-bot** — Telegram-бот подачи заявок на оплату счетов для небольшой
компании. Сотрудник заполняет форму (сумма, валюта, контрагент, статья,
плановая дата/срочность, комментарий, файл счёта *или* реквизиты), бот
сохраняет файл счёта, пишет строку в реестр и шлёт каждому финансисту карточку
заявки с кнопками статуса (срочные помечаются 🔴). Итог заявки (без
чувствительных данных) может публиковаться в рабочую группу/канал.

Хранилище **переключаемое** (`STORAGE_BACKEND`): `google` — Google Sheets +
Google Drive (колонки реестра — по ТЗ, «Ссылка на счет» = webViewLink с
правами папки), `local` — SQLite как источник правды + живое xlsx-зеркало
(шаблон «Реестр.xlsx» из ТЗ) + каталог файлов. Необязательное xlsx-зеркало
(`REGISTRY_XLSX_FILE`) заполняется и в Google-режиме. Все обращения к
реестру/файлам — через фасад `services/storage.py`. CSV упразднён.

## 2. Два канала ввода

1. **Mini App (основной, включается `WEBAPP_URL`)** — страница-форма
   `webapp/index.html` открывается внутри Telegram (web_app кнопка), данные
   уходят POST-запросом в собственный API `POST /api/invoice` с файлом счёта.
   Красивый ввод: всё на одном экране, MainButton, тема Telegram, валидация на
   лету.
2. **Чат-форма (fallback, работает при пустом `WEBAPP_URL`)** — пошаговый
   `ConversationHandler`: сумма → валюта → контрагент → статья → срочность
   (срочно/обычная — дата считается сама, настраиваемая — ввод даты) →
   комментарий (необязателен) → файл/реквизиты → подтверждение. Таймаут
   диалога 10 минут; прогресс переживает рестарт (PicklePersistence).

Оба канала сходятся в `services/intake.py::finalize_submission` — единственной
точке, где заявка пишется в реестр и рассылаются уведомления. Записи в реестре
идентичны независимо от канала.

## 4. Поток Mini App (последовательность)

1. Пользователь жмёт кнопку (личка: web_app кнопка → `WEBAPP_URL?return_chat=`;
   группа/канал: с заданным MINIAPP_SHORT_NAME — прямая ссылка
   `t.me/<бот>/<имя>?startapp=<chat_id>`, форма открывается поверх чата, id
   чата приходит в форму как `start_param`; без него — deep-link в личку,
   т.к. web_app кнопки работают только в приватных чатах). В группу/канал
   кнопка публикуется автоматически при добавлении бота (my_chat_member) или
   по /menu; в канале бот должен быть админом с правом публикации (иначе не
   сможет ни постить кнопку, ни проверять подписку через getChatMember).
2. Страница валидирует ввод, шлёт `POST /api/invoice` (multipart) с заголовком
   `X-Telegram-Init-Data`.
3. Бэкенд: проверка подписи initData → whitelist → валидаторы (те же, что в
   чат-форме) → сохранение файла → `finalize_submission`.
4. `finalize_submission`: строка в реестр → финансистам ОДНО сообщение
   (файл счёта или PDF заявки с карточкой-подписью и кнопками статуса) →
   автору ОДНО сообщение (PDF с подтверждением-подписью) → итог в группу
   `return_chat` (только если автор — участник группы, `getChatMember`).
5. Страница показывает «Заявка принята» и закрывается; подтверждение приходит
   в чат с ботом.

## 5. Модель безопасности

- **Аутентификация API** — только подпись Telegram initData (HMAC c ключом от
  токена бота); подделать снаружи нельзя, возраст ≤ 1 часа. Без валидной
  подписи — 401.
- **Авторизация** — whitelist `ALLOWED_USER_IDS` + добавленные админом
  (в обоих каналах). **Fail-closed**: пустой список = доступ закрыт для всех,
  кроме админов из ADMIN_IDS.
- **Даты — только на сервере** (`bot/scheduling.py`, TIMEZONE): срочно →
  сегодня, обычная → следующий рабочий день (пт/вых → пн); клиент шлёт
  `planned_date=auto`. Инъекция формул: Sheets — RAW + OVERWRITE (чужая шапка
  не изменяется), xlsx — `excel_safe`. Реестр пишет подтверждённое ФИО
  из `EMPLOYEE_NAMES`, а не имя профиля. Полная модель угроз — SECURITY.md.
- **`return_chat` из URL может быть подделан** → перед публикацией итога в
  группу проверяется членство автора в этой группе.
- **HTML-инъекции** — все пользовательские строки эскейпятся перед отправкой с
  `parse_mode=HTML`.
- Секреты только в `.env` и `secrets/` (оба в `.gitignore`); тела запросов
  Telegram не логируются.
- Лимит файла 20 МБ (клиент, API и `request_body` в Caddy — 25 МБ с запасом).
- **Rate limit** подачи: не более 5 заявок в минуту на пользователя (429).
- **Санитизация имён файлов**: расширение и контрагент чистятся до безопасных
  символов — path traversal через имя файла исключён (покрыто тестами).
- Защитные заголовки API (nosniff, no-referrer, no-store).
- callback_data статусов проверяется по формату ID заявки.
- **Google-режим**: файлы наследуют права папки, публичные ссылки не создаются;
  доступ к таблице/папке — только у service account и уполномоченных лиц.
- **Дедуп**: повторная подача того же счёта в окне 14 дней требует явного
  подтверждения (чат — кнопки, Mini App — 409 + confirm); подтверждённые
  дубли фиксируются в аудите.
- **Аудит-журнал** в SQLite (`SECURITY_DB_FILE`): структурированные события
  с user_id/username/временем — расследуемость для СБ, не зависит от ротации
  stdout-логов. Просмотр — /audit.
- **Админы бота = ADMIN_IDS + администраторы доверенных чатов** (куда бота
  добавил существующий админ); кэш проверки 5 минут.

## 6. Принятые решения и почему

- **Бот остаётся на long polling даже с API.** HTTPS нужен только странице
  Mini App и её API; webhook Telegram не обязателен. Меньше конфигурации,
  проще локальная отладка.
- **Один процесс: PTB + uvicorn в одном event loop.** API шлёт сообщения тем же
  Bot-инстансом (подтверждения, карточки финансистам) без очередей и второго
  токена.
- **Caddy, а не nginx+certbot, в докер-варианте** — автоматический выпуск и
  продление сертификатов без ручных шагов.
- **Форма — одна статическая страница без сборки и фреймворков** — нечему
  ломаться, нет node_modules; отдаётся тем же FastAPI.
- **`WEBAPP_URL` пуст → полный откат на чат-форму** — деградация без правки кода.
- **SQLite + xlsx-зеркало вместо CSV** — транзакции и UNIQUE по ID заявки
  против гонок и дублей, при этом «файл, который открывается в Excel»
  сохранён как зеркало; замена бэкенда локализована в `services/`.

## 7. Исправлено в этой итерации (2026-08-03)

- Коллизия ID заявок в одну секунду — в ID добавлен суффикс из telegram_id.
- Номер записи в CSV считался по физическим строкам — ломался на многострочных
  комментариях/реквизитах; теперь через `csv.reader`.
- Сбой уведомления финансиста показывал пользователю ложное «не удалось
  сохранить» — уведомления отделены от записи в реестр (`intake.py`).
- Захардкоженный Windows-путь по умолчанию для `STORAGE_DIR` — теперь
  `./storage` от каталога проекта.
- Запись справочника пользователей блокировала event loop — вынесена в
  `asyncio.to_thread`.
- Неэскейпленный контрагент в HTML-подтверждении (падение отправки на `<`).
- Публикация итога в произвольную группу по подделанному deep-link — теперь
  проверка членства.

## 8. Известные ограничения / роадмап

- **Статусы заявок — сделано полностью**: кнопки на карточке, «Отклонено» и
  «Отложено» запрашивают у финансиста причину (текстом или «Без причины»),
  автор получает уведомление с причиной, карточки обновляются у ВСЕХ
  финансистов (services/cards). «Оплачено» применяется мгновенно.
- **Файл счёта финансисту — сделано** (вложение к карточке).
- **Админ-настройки из Telegram — сделано** (⚙️ в Mini App + команды);
  список админов задаётся только в .env (ADMIN_IDS) — защита от самозахвата.
- **Тесты — сделано**: ~170 pytest (валидаторы, initData-подпись,
  интеграционные тесты API через ASGI, e2e чат-формы, реестр SQLite и
  xlsx-зеркало, Google-бэкенд на моках, автопроверка счёта, PDF, бэкап)
  + 8 JS-тестов зеркала валидаторов; гоняются в CI. Европейские форматы
  сумм («1.000.000,50») парсятся корректно.
- **Persistence чат-формы — сделано** (PicklePersistence, только user_data).
- **Google-бэкенд (Sheets + Drive) — сделано и проверено вживую**; для Drive
  на личном аккаунте — OAuth-токен владельца (см. README).
- `/report` для финансиста (сводка за период) — идея.

## 9. Как запускать

- **Прод**: см. `DEPLOY.md` (Docker Compose + Caddy, HTTPS автоматически).
- **Локально без HTTPS**: `WEBAPP_URL` пустой → `python main.py` (чат-форма).
- **Локально с Mini App**: туннель (cloudflared/ngrok) → его https-URL в
  `WEBAPP_URL`.
