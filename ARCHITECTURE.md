# Архитектура решения и стоимость реализации

Краткое описание архитектуры **invoice-bot** по пунктам ТЗ: использованные
технологии, хранение информации, идентификация пользователя, меры защиты,
работа с Google Таблицей и Google Drive — и подсчёт стоимости реализации.

Подробные решения и их причины — в [CONTEXT.md](CONTEXT.md), модель угроз —
в [SECURITY.md](SECURITY.md), деплой — в [DEPLOY.md](DEPLOY.md).

---

## 1. Общая схема

Сотрудник подаёт заявку одним из двух каналов — **форма Mini App** (страница
внутри Telegram) или **пошаговая чат-форма** `/invoice`. Оба канала сходятся
в одной точке финализации: заявка попадает в реестр, файл счёта — в хранилище,
каждый финансист получает карточку с кнопками статуса, автор — подтверждение
с PDF-документом заявки.

После подачи автор не теряет заявку из виду: экран **«Мои заявки»** (кнопка 📋
в форме, команда `/my` в чате) показывает статусы, причины отказа и даёт две
операции — повтор заявки и отзыв, пока её не тронул финансист.

```
 Сотрудник ──── Mini App (HTTPS) ───▶ Caddy ──▶ FastAPI /api/invoice ──┐
     │                                                                 ├─▶ finalize_submission
     └──── чат-форма /invoice ─────▶ Telegram Bot API ──▶ PTB-бот ─────┘         │
                                                                    ┌────────────┼────────────┐
                                                                    ▼            ▼            ▼
                                                          Реестр (Sheets     Файл счёта    Карточки
                                                          или SQLite+xlsx)   (Drive или    финансистам,
                                                                              каталог)     PDF автору
```

Один процесс: бот (long polling) и uvicorn с FastAPI работают в одном event
loop и делят один Bot-инстанс. Webhook не нужен — HTTPS требуется только
странице Mini App и её API.

## 2. Использованные технологии

| Слой | Технология | Зачем |
|---|---|---|
| Бот | Python 3.11, `python-telegram-bot` 21 (async) | Чат-форма (ConversationHandler), кнопки статусов, админ-команды, persistence |
| API | FastAPI + uvicorn | Приём заявки из Mini App (multipart), админ-панель, healthcheck |
| Фронт | Mini App: один HTML-файл без сборки и фреймворков | Форма в теме Telegram; JS-валидаторы — зеркало серверных, покрыты тестами |
| HTTPS | Caddy | Автоматические сертификаты Let's Encrypt, reverse proxy |
| Реестр | Google Sheets **или** SQLite + xlsx-зеркало (openpyxl) | Переключается `STORAGE_BACKEND`, формат — шаблон «Реестр.xlsx» из ТЗ |
| Файлы | Google Drive **или** локальный каталог | webViewLink в реестре, права папки |
| Google API | `google-api-python-client`, `google-auth(-oauthlib)` | Service account для Sheets, OAuth-токен владельца для Drive |
| PDF | reportlab (+ `num2words`, шрифты DejaVu вендорены) | Документ заявки на фирменном бланке, сумма прописью |
| Автопроверка счёта | pypdf (текстовый слой) + Tesseract OCR (rus+eng) | Скоринг маркеров «это счёт», мягкое предупреждение |
| Конфигурация | pydantic-settings + `.env` | Секреты вне кода, типизированные настройки |
| Развёртывание | Docker Compose (non-root, cap_drop ALL) / systemd | Плюс WARP-прокси для хостингов, где Telegram API недоступен напрямую |
| Тесты и CI | pytest (~305), node --test (8), ruff, GitHub Actions | Линт → тесты → смоук-импорты → сборка образа на каждый push |

## 3. Как хранится информация

- **Google-режим** (`STORAGE_BACKEND=google`): реестр — Google Таблица
  (первые девять колонок — ровно по шаблону ТЗ, правее — служебные), файлы
  счетов — папка Google Drive, ссылка в реестре — webViewLink. Параллельно
  ведётся локальное xlsx-зеркало.
- **Локальный режим** (`local`): источник правды — **SQLite**
  (транзакции, UNIQUE по ID заявки — защита от гонок и дублей), рядом —
  живое **xlsx-зеркало** в формате шаблона «Реестр.xlsx» (его же присылает
  команда `/export`); файлы счетов — каталог на диске.
- **Служебные данные**: аудит-журнал и отпечатки дедупа — SQLite; справочник
  пользователей и runtime-настройки (финансисты, whitelist, бэкап, напоминания) — JSON.
- Всё лежит в одном каталоге `data/` (в Docker) — его же архивирует
  встроенный ежедневный бэкап с ротацией и отправкой админу в чат.
- Все обращения к реестру и файлам — только через фасад
  [services/storage.py](services/storage.py); синхронный I/O — в
  `asyncio.to_thread`, event loop не блокируется.

## 4. Как определяется пользователь

- **Чат-форма**: Telegram `user_id` приходит в каждом update от Telegram Bot
  API — подделать его вне Telegram нельзя.
- **Mini App**: страница шлёт заголовок `X-Telegram-Init-Data`; сервер
  проверяет **подпись HMAC-SHA256** (ключ выводится из токена бота, схема
  «WebAppData»), возраст подписи ≤ 1 часа. Без валидной подписи — 401,
  данным из URL/формы о личности пользователя сервер не верит.
- **Авторизация — whitelist, fail-closed**: пустой список = доступ закрыт
  для всех, кроме админов из `ADMIN_IDS`. Роли: сотрудник (подаёт),
  финансист (меняет статусы), админ (`ADMIN_IDS` + администраторы
  доверенных каналов/групп — панель ⚙️ и команды).
- В реестр пишется **подтверждённое ФИО** из справочника `EMPLOYEE_NAMES`,
  а не переименовываемое имя Telegram-профиля.

## 5. Меры защиты конфиденциальных данных

- Подпись initData на каждом API-запросе; rate limit подачи (5/мин) и
  предпроверки файла (10/мин); защитные заголовки (nosniff, no-store).
- **Дедуп платежей**: SHA-256-отпечаток ключевых полей, окно 14 дней,
  повторная подача требует явного подтверждения — защита от двойной оплаты.
- **Аудит-журнал** (SQLite): отказы доступа, подачи, смены статусов с
  причинами, подтверждённые дубли — просмотр командой `/audit`.
- **Против инъекции формул**: Google Sheets — только `RAW` +
  `OVERWRITE`, xlsx — экранирование ячеек, начинающихся с `= + - @`.
- Все пользовательские строки — через `html.escape`; имена файлов
  санитизируются (path traversal исключён); реквизиты в карточках — под
  спойлером Telegram.
- В логи не попадают суммы, реквизиты и содержимое файлов; секреты —
  только в `.env` и `secrets/` (в `.gitignore`).
- Контейнер: non-root (uid 1000), `cap_drop: ALL`,
  `no-new-privileges`; systemd-вариант закалён аналогично.
- Полная таблица «угроза → мера → код» — в [SECURITY.md](SECURITY.md).

## 6. Работа с Google Таблицей и Google Drive

- **Sheets** — через **service account** (JSON-ключ в `secrets/`), таблица
  расшарена на его email как «Редактор». Запись — `append` с
  `valueInputOption=RAW` и `insertDataOption=OVERWRITE`; готовую шапку
  таблицы бот не переписывает, пустой лист размечает и оформляет сам
  (закреплённая шапка, фильтр, форматы сумм, подсветка статусов).
  Смена статуса находит строку по ID заявки и обновляет одну ячейку.
- **Drive** — загрузка файлов идёт **от имени владельца папки** через
  OAuth-токен (одноразовая настройка `scripts/google_oauth_setup.py`):
  у service account с 2025 года нет собственной квоты хранилища на личных
  аккаунтах. Файл получает только права папки, публичные ссылки не
  создаются; в реестр пишется webViewLink.
- Сбой Google API не роняет заявку молча: автор получает честную ошибку,
  админы — алерт (с троттлингом повторов).

## 7. Стоимость реализации

### Инфраструктура (Timeweb Cloud, цены ~август 2026)

| Статья | Конфигурация | Цена |
|---|---|---|
| VPS [Timeweb Cloud](https://timeweb.cloud/) — минимум | 1 × CPU, 1 ГБ RAM, 15 ГБ NVMe | ≈ 250–300 ₽/мес |
| VPS — комфортно (с OCR-автопроверкой) | 2 × CPU, 2 ГБ RAM, 30 ГБ NVMe | ≈ 500–700 ₽/мес |
| Домен `.ru` (нужен для HTTPS Mini App) | регистрация/продление | ≈ 300–900 ₽/год |
| TLS-сертификат | Let's Encrypt через Caddy, автопродление | 0 ₽ |
| Telegram Bot API, Mini App | — | 0 ₽ |
| Google Sheets / Drive API | в рамках бесплатных квот | 0 ₽ |
| Обход блокировки api.telegram.org | Cloudflare WARP (socks5-контейнер) | 0 ₽ |
| Весь софт-стек | Python, PTB, FastAPI, Caddy, Docker, Tesseract — open source | 0 ₽ |

**Итого эксплуатация: ≈ 3 900–9 300 ₽/год** (минимальная и комфортная
конфигурации соответственно). Один сервер обслуживает компанию целиком —
нагрузка бота для VPS ничтожна.

| Этап | Часы |
|---|---|
| Проектирование, схема данных, ТЗ-разбор | 8 |
| Чат-форма (13 состояний, подтверждение, дедуп) | 16 |
| Mini App: страница, JS-валидаторы, черновик, админ-панель | 24 |
| API + подпись initData + rate limit | 10 |
| Google-контур (Sheets RAW/статусы/оформление, Drive OAuth) | 14 |
| Хранилище: SQLite + xlsx-зеркало + фасад | 10 |
| PDF-документ, автопроверка «похоже на счёт» (OCR) | 12 |
| Безопасность: аудит, алерты, бэкапы, hardening | 12 |

При ставке разработчика 1 500–3 000 ₽/час это **≈ 195 000–390 000 ₽**
разовых затрат. Фактическая реализация велась с AI-ассистентом
(Claude Code), что сжало календарные сроки до нескольких дней.
