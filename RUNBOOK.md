# Что делать, если — Оплатыч

Одна страница на случай «бот молчит» или «пришла ошибка». Для того, кто
не писал этот код. Подробности — в [DEPLOY.md](DEPLOY.md), решения и их
причины — в [CONTEXT.md](CONTEXT.md).

**Первое правило.** Заявка, попавшая в реестр, уже не потеряется: карточка,
PDF и уведомления вторичны. Проверьте реестр, прежде чем что-то чинить.

```bash
cd /opt/invoice-bot
docker compose ps                 # что живо
docker compose logs -f app        # что говорит бот
docker compose restart app        # лечит большинство разовых сбоев
```

---

## Симптомы

| Что видно | Скорее всего | Что делать |
|---|---|---|
| Бот не отвечает в чате | пропала связь с Telegram | `docker compose logs app \| tail -30` → NetworkError? Ждать 5 мин, затем `docker compose restart warp app` |
| Форма не открывается | упал контейнер или Caddy | `docker compose ps`, поднять упавший: `docker compose up -d` |
| Заявка подана, карточки нет | получателей нет или у них фильтр | ⚙️ → Доступ → Финансисты; ⚙️ → Напоминания → «только срочные»? |
| «Не удалось сохранить заявку» | недоступна Google-таблица | Проверить доступ сервисного аккаунта к таблице; заявка НЕ записана, просить подать заново |
| Заявки не пишутся в таблицу | отозван доступ / нет листа с нужным gid | `docker compose logs app \| grep -i google` |
| Никто не получает напоминания | выключены или не тот час | ⚙️ → Напоминания, кнопка «Проверить на себе» |
| В реестре чужое имя | человека нет в справочнике | ⚙️ → Доступ → Справочник сотрудников → добавить, затем «Обновить ФИО в реестре» |
| Долгие ответы формы | моргает прокси | Норма при 1–2 с; дольше 10 с — `docker compose restart warp` |

## Проверки

```bash
# Всё ли согласовано: реестр, зеркало, бэкап
docker exec -e PYTHONPATH=/app -w /app invoice-bot-app-1 \
  python -c "import asyncio;from services import registry_check as c;\
print(c.describe(asyncio.run(c.check())))"

docker exec -e PYTHONPATH=/app -w /app invoice-bot-app-1 \
  python scripts/verify_backup.py         # разворачивает последний архив
```

В приложении: ⚙️ → **Здоровье бота** — связь, последние сбои, журнал
инцидентов. 📈 **Аналитика** — сколько заявок висит и что просрочено.

## Восстановление

Архивы: `data/backups/*.tar.gz`, ежедневно, хранятся последние N, копия
приходит админу в личку.

```bash
docker compose stop app
tar -xzf data/backups/ИМЯ.tar.gz -C data
chown -R 1000:1000 data
docker compose start app
```

**Чего в архиве НЕТ на google-бэкенде:** счетов и PDF — они живут только
в Google Drive, и это осознанное решение заказчика, а не недоделка. Реестр
в архиве есть — файл `Реестр.xlsx`. Если пропала папка Диска, вложения
восстановить неоткуда: беречь надо доступ к ней.

## Чего НЕ делать

- **Не править `data/bot_settings.json` руками.** Настройки живут в памяти
  процесса и с диска не перечитываются: правка не подействует, а первым же
  сохранением бота будет затёрта. Состав финансистов, whitelist и админов
  меняются только в ⚙️ или командами бота.
- **Не пересоздавать контейнер `warp`** без нужды: 25.08.2026 это дважды
  роняло боевой контур. Хватает `docker compose restart warp`.
- **Не выкатывать непроверенное:** `pytest -q` и `npm run test:e2e` перед
  `docker compose up -d --build app`. Стенд пересобирается ОТДЕЛЬНО.
- **Оформление листа ставится ОДИН раз.** Изменили код оформления —
  существующий лист его не получит: страж считает лист готовым. Применить
  заново: `docker exec -e PYTHONPATH=/app -w /app invoice-bot-app-1 python -c
  "from services import google_backend as g; from config import settings;
  g._sheets().spreadsheets().batchUpdate(spreadsheetId=settings.google_sheet_id,
  body={'requests': g._style_requests(0, with_banding=False)}).execute()"`
  (`with_banding=False` — повторный addBanding отвечает 400 и роняет пачку).
- **Не удалять строки в Google-таблице** — бот об этом не узнает, а сверка
  зеркала поднимет алерт только после ближайшего бэкапа.
